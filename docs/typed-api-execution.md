# Typed API execution

Generated API capabilities expose the pinned CLI's common execution options alongside their method metadata: typed parameter flags, raw params/data JSON, pagination controls, multipart file input, binary output, jq and output formats. Typed parameter flags override matching raw params keys. Declared empty query values are omitted; unknown raw query keys remain an intentional escape hatch. Required pagination fields are optional when page-all supplies the cursor lifecycle.

Path identifiers are validated before URL encoding. Body methods accept raw JSON even when the catalog declares no body. Local paths and stdin are represented by private grant-owned artifact references in the hosted service. A file defaults to the sole declared file field, otherwise `file`; multipart requests require an object body and cannot combine with binary output or pagination. Previews validate inline inputs without upstream writes and defer artifact hydration when no grant context is available.

Typed and raw API commands share one execution engine for pagination, transfer and formatting. Typed workflows retain their original business domain and read/write risk so using a calendar API does not require authorization for a separate raw API domain. Pagination remains resumable, honors limits and inter-page delays, merges the upstream collection shape, and reports truncation accurately. Binary responses are private artifacts rather than local files. Grant authorization replaces interactive terminal confirmation; compatibility `yes` is accepted without weakening authorization.

Terminal presentation is adapted to MCP structured output: non-JSON formats return records plus their requested format and metadata instead of terminal tables or local stdout streams. Existing simple JSON calls retain their direct business-data response shape. Explicit null request bodies remain null. Advanced execution uses domain-scoped workflows, and output filenames identify private artifacts rather than filesystem paths.
