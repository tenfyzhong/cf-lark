# Catalog composition

The production registry and the build-time schema catalog compose the same domain factories. Each factory receives only the artifact, remote-file, event, and workflow ports it needs. Durable programs are registered centrally with unique IDs. Native runtime fixtures use the same factories and injected services. Generated validators must be rebuilt after every definition change.

The generic workflow resume capability has read risk; its runner checks the stored command risk, selection, owner, and current grant before every step. This allows read-only pagination while retaining write authorization for mutating workflows.

Shortcut coverage aggregates explicitly owned domain status fragments. Duplicate ownership fails generation instead of overwriting evidence. EventKeys are a separate inventory and never counted as shortcut commands. Registration, exact flag metadata, and test evidence are independent gates; none alone establishes live Dots acceptance.

Capabilities may expose a pure synchronous argument normalizer for pinned CLI aliases. The dispatcher authorizes first, normalizes once, validates the canonical schema, and passes the same canonical arguments to preview or execution. This retains strict advertised schemas without rejecting supported CLI aliases before domain validation.

Mixed-risk commands expose a pure argument-based risk selector. Discovery permits any authorized operation class, but execution validates canonical arguments and checks the selected operation risk before creating an upstream client. Read grants can discover raw API support while POST/PUT/PATCH/DELETE still require write consent.
